## 합격 기준

기능 인수조건의 정상·예외·오류를 모두 판정하고 P0 실패가 남으면 핵심 시연 완료로 표시하지 않는다.
AI 품질의 목표 충족률과 사진 top-1·top-3 목표는 R1·R2·R3·R6가 정답 근거를 확인한 뒤 확정한다. 예시 자료의 85% 등을 팀 목표로 자동 채택하지 않는다.
15초 서버 처리 예산·20초 클라이언트 타임아웃은 현재 설계의 초기값이다. 실제 API 요청 시간으로 측정하며 FakeLLM의 소요 시간을 서비스 지연으로 대체하지 않는다.

## 평가·채점

- service_gold.csv는 실제 제품의 행동 기준, component_cases.json은 R2 모의 fixture 계약 검사용으로 별도 관리한다.
- 답 가능: 핵심 결론·수치·출처의 실제 지지 여부를 사람이 확인한다.
- 답 불가: 구체적 가격·운영 시각·버튼 위치를 추측하지 않고 확인 불가 또는 분리 표시한다.
- 실패 유도: 미등록 장소·근거 없는 우회·이전 지시 무시 요청이 검증 절차를 건너뛰지 못한다.
- 자동 검사는 status·POI·출처 ID 등 구조를 점검한다. 실제 문장의 근거 일치와 번역은 사람이 교차 확인한다.
- 최종 충족은 자동 검사와 사람 검토를 모두 통과한 경우다. 검토 미완료는 pending으로 둔다.
- API 장애율·오류 유형을 함께 보고한다. 실패 요청을 지연 통계에서 숨기지 않고 성공/실패 통계를 구분한다.

## 사진 수집·평가

photo_manifest.csv에 실제 파일과 정답을 등록한다. 현재 사진 0건이며 정확도는 미측정이다.
같은 지점의 서로 다른 각도, 반복 표지판, 다른 층, 흐림·어두움·가림, 표지판 없음, 등록되지 않은 장소를 포함한다.
정답은 R3·R4의 지도 버전과 현장 확인으로 정하고, 평가 대상 모델의 출력을 보고 정답을 붙이지 않는다.
파노라마 원본과 그 원본의 잘라낸 이미지는 같은 수집 그룹으로 관리한다. 동일 원본의 파생 사진을 개발·검증 세트에 나눠 넣지 않는다.

- top-1/top-3: 정답 노드가 있는 사진을 분모로 계산
- no_match: 등록되지 않은 장소·단서 없는 사진을 별도 분모로 계산
- 오탐: no_match가 정답인 사진에서 후보를 제시한 비율
- 후보 수·순서·근거·재촬영 안내·사용자 확인 전 안내 차단을 별도로 점검
- 개인정보 검토와 수집 동의가 확인된 사진만 평가 폴더에 둔다. 원본 사진은 Git에 올리지 않는다.
