# QA #3 근거·검색 평가 보완 — 2026-10-23

대상: [QA #3](https://github.com/team-onetruck/oneload-qa/issues/3). R3 요청의 자료를 검토해 QA 범위에서 수정했다. 운영 설정이나 다른 역할의 패치는 적용하지 않았다.

## 반영한 내용

- 서비스 정답 초안을 `r6-service-v2`로 올리고 이전 CSV를 `eval/archive/service_gold-v1.csv`에 보존했다. 해시·변경 사유는 [메타데이터](../eval/service_gold.meta.json)에 있다.
- Q10은 `답가능`: 열차·구간·카드 조건을 확인하거나 조건별로 나누어 요금 근거와 문서 확인일을 표시한다. 실시간 가격이라고 보증하지 않는다. 근거 없는 금액 생성은 여전히 실패다.
- Q01~20의 source_doc/source_locator에 R3 문서·공식 URL·문서 확인일/확인자 또는 Agent/Backend 행동 계약을 매핑했다. 목적지 문항은 실제 지도 POI와 교차 확인하도록 표시했다.
- 직통 결제 수단, 개찰구·환급기 정확한 위치, 기기별 해외 카드·버튼 정보는 미확인 부분으로 유지했다. 문서 매핑을 사실 검증 완료로 간주하지 않으며 20건 모두 `mapped_pending_human_review`, 실제 출력·채점은 빈칸이다.
- 모의 검색용 component v2의 20시나리오/21턴·기대값·SHA는 그대로 유지했다.

R3 매핑은 RAG `4a967b3`의 `docs/qa-source-map.md`를 기준으로 한다. 개별 지식 문서의 verified_at·verified_by는 원문 기록이며 R6 사람 검토를 의미하지 않는다.

## 검색 평가와 임계값 판정

[질문 32개](../eval/retrieval_cases.json) · [실행기](../scripts/evaluate_retrieval.py) · [전체 증거](../reports/retrieval-evaluation.json)

질문·정답·분할·목적식·출고 기준을 첫 검색 실행 전에 고정했다. R6 합성 질문으로 개발16건(양성10/범위밖6), holdout16건(양성10/범위밖6)을 구성했다. 같은 질문군은 두 세트에 걸치지 않는다. 같은 문서 코퍼스를 사용하므로 완전히 독립된 현장 검증은 아니다.

개발셋만으로 0.10~0.60(0.05 간격)을 비교했다. k=3·상대 컷오프0.5는 고정하고 목적식 `2TP/(2TP+FN+2FP)`를 최대화했다. TP는 양성 top3 적중, FN은 양성 미적중, FP는 범위밖 비어있지 않은 결과다. 동점이면 FP가 적은 값, 낮은 임계값 순으로 선택했다. 기존 R3 44문항은 선택에 사용하지 않았다.

| 평가셋 | min_score | 1위 적중 | top3 적중 | 범위밖 빈 결과 |
|---|---:|---:|---:|---:|
| R6 개발 | 0.35 | 보고서 참조 | 9/10 | 5/6 |
| R6 holdout | 0.35 | 보고서 참조 | 10/10 | 4/6 |
| R3 기존 진단 | 0.25 | 32/40 | 38/40 | 3/4 |
| R3 기존 진단 | 0.35 | 30/40 | 35/40 | 4/4 |

아래 출고 조건은 R6의 임계값 검토용 잠정 기준이며 팀의 최종 서비스 품질 목표를 확정한 것은 아니다.

**운영 임계값 확정 보류.** 0.35는 개발 목적식이 선정한 실험 후보다. 출고 조건(개발·holdout 각각 양성 top3≥90%, 범위밖 오탐0)을 충족하지 못했다. 개발 후보 중에도 두 조건을 동시에 만족한 값이 없었다. 기존 R3 양성의 회귀도 있으므로 RAG 기본값0.25를 변경하지 않았다.

holdout에서 호텔 객실 가격 질문에 express-ticket/help-desks, 실시간 잔여석 질문에 express-ticket이 반환됐다. 이는 검색 단계 오탐이며 실제 LLM의 잘못된 답변을 측정한 것은 아니다. [RAG #3](https://github.com/team-onetruck/oneload-rag/issues/3)에서 개선을 요청했다.

이번 holdout은 이미 관찰·공개됐다. 다음 개선 때 이 결과로 최적화한 뒤 같은 holdout을 미관찰 검증이라고 소개하지 않는다. 별도 새 holdout과 기존 회귀셋을 함께 사용한다. top3 중 정답 하나라도 있으면 적중이므로 인용 정밀도·답변 사실성·여행객 품질은 이 점수로 판단할 수 없다. pgvector·실제 임베딩은 이번에 실행하지 않았다.

## 실제 RAG 주입 API 검사

[API 21/21 증거](../reports/rag-integration-probe.json). Backend 493884f, Agent 250271e, Data 606f648, RAG 4a967b3. FakeLLM·합성 JPEG·일회용 PostgreSQL·공식 문서 MemorySearch(k=3,min_score=0.35)다.

- 요금 질문: answered + `doc-fare-arex-express` + URL·verified_at 전달.
- 빈 검색 대조군: cannot_answer·출처 없음·금액 추측 없음.
- 사진 질문 출처·같은 Vision 주입, 카드 슬롯, 등록 경로, 후보 확인, 사진 no_match, LLM fallback, Vision 장애503을 함께 재검사했다.
- 환경변수의 pgvector/커뮤니티/지식 폴더 설정을 따르지 않는다. RAG 커밋·코드·지식 해시와 실행 중 입력 불변을 확인했다. RAG 누락은 Docker 전에 실패한다.

이것은 QA의 명시적 주입 경로 검사다. Backend 기본 entrypoint는 여전히 RuleAgent/NoVision(INT-07)이며, 운영 연결 이후의 재검사를 대체하지 않는다. 실제 모델·임베딩 호출0회, 현장 사진 정답0건, 사실성 사람 검토 미완료다.
